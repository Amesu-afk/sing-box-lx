# 015 - olcRTC

## Назначение

TarnVPN принимает одиночные `olcrtc://`-профили и HTTPS-подписки с такими
профилями, показывает каждый узел отдельной записью и подключает выбранный узел
как WebRTC-туннель через поддерживаемый сервис видеосвязи.

## Контролируемые параметры

- `provider`: `jitsi`, `telemost` или `wbstream`;
- `transport`: `datachannel`, `vp8channel`, `seichannel` или `videochannel`;
- room ID/URL и 32-байтовый hex-ключ;
- параметры выбранного транспорта из payload URI;
- пользовательское имя после `$`.

Текущая Android-реализация уже принимает Jitsi и Telemost с `datachannel` /
`vp8channel`. WB Stream и транспорты SEI/video остаются целевым расширением;
до его реализации их ссылки отклоняются при импорте.

Локальный SOCKS5-интерфейс является внутренней деталью приложения. Нативная
Android-сборка включает olcRTC только с build-tag `with_olcrtc`.

## Входы

- одиночный `olcrtc://` URI v1;
- manager QR URI с `provider@room:1/<room>` и query-параметрами;
- HTTPS-подписка `sub.md`, содержащая строки `olcrtc://` и метаданные `#`/`##`;
- QR-код с одиночным URI или HTTPS URL подписки;
- выбор импортированного профиля пользователем;
- запуск, остановка, перезапуск и смена сети Android VPN-сервиса.

## Выходы

- отдельный сервер в списке TarnVPN для каждого корректного URI;
- локальный SOCKS5-выход активного olcRTC-клиента;
- весь трафик выбранного VPN-профиля через этот выход;
- RTT активного туннеля по его шифрованному контрольному каналу, без отдельного TCP-пробника;
- явная ошибка импорта или старта при некорректном профиле.

## Data flow

1. Приложение получает URI либо скачивает HTTPS-подписку.
2. Валидные записи превращаются в отдельные профили, исходный URI сохраняется.
3. Перед запуском VPN выбранный URI настраивает нативный olcRTC-клиент.
4. После готовности SOCKS5 приложение запускает sing-box и направляет в него TUN.
5. При остановке, ошибке или смене профиля обе части завершаются совместно.

## Правила и гарантии

- ключ должен быть ровно 32 байта hex;
- неизвестные provider, transport и transport-параметры отвергаются до записи;
- room не может быть пустым;
- sing-box не стартует до готовности olcRTC SOCKS5;
- сокеты olcRTC защищаются от обратного попадания в Android VPN;
- неполное обновление подписки не удаляет прежние рабочие профили;
- ключи и room не пишутся в обычные диагностические сообщения приложения.
- пинг не выдаётся для неподключённого olcRTC-профиля или при устаревшем ответе контроля.

## Границы

- только Android-клиент; desktop и серверная сторона olcRTC не входят в фичу;
- QR-бандлы `olcrtc+gz` и encrypted mirror не входят в первую задачу;
- приложение не разворачивает сервер и не создаёт комнаты;
- конкретный provider зависит от доступности его SFU и версии сервера.

## Особенности сопровождения

olcRTC и libbox собираются одним вызовом gomobile: две независимые AAR с Go
runtime конфликтуют в одном Android-приложении. Зависимость фиксируется на
точном коммите, а обе API 23/API 21 AAR проверяются вместе.
