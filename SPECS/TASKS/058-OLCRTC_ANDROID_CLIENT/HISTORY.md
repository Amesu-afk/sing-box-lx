# История решения

Изначально Android controller останавливал и запускал olcRTC при каждом
`serviceReload`, даже если выбранный URI не менялся. Это позволяло обычной
перезагрузке настроек или сетевому recovery прервать уже поднятый WebRTC
туннель. На телефоне Telemost сначала подключился, затем приложение показало
`read welcome: handshake: read body: timeout`; журнал sing-box при этом
показывает уже запущенный локальный SOCKS5. Причина самого timeout без
серверного журнала остаётся неподтверждённой.

Текущая схема сохраняет активный runtime при неизменном исходном URI и
доверяет его собственному reconnect. Смена URI, полная остановка службы или
уже завершившийся native runtime по-прежнему приводят к новому старту.
