|------|----------|
| Тип | F |
| Статус | C (complete) — URI/sub.md импорт, общий AAR и Android lifecycle реализованы; Telemost работает по сообщению пользователя, отображение RTT ждёт проверки на телефоне |

## Актуальная архитектура

Android AAR одним gomobile-вызовом экспортирует libbox и зафиксированный mobile
API olcRTC, поэтому в процессе существует один Go runtime. Импортёр разбирает
URI v1 и `sub.md`, сохраняет исходный URI рядом с обычным профилем и генерирует
sing-box-конфиг с локальным SOCKS5 outbound. VPN-сервис запускает olcRTC до
sing-box, ждёт готовности и останавливает его на всех путях teardown. Перезагрузка
sing-box с тем же исходным URI сохраняет работающий olcRTC runtime: собственный
WebRTC reconnect не должен прерываться повторным стартом по настройке VPN.
Смена URI или остановленный runtime требуют нового запуска.

Для активного профиля приложение читает RTT существующего ping/pong контрольного
канала olcRTC. Значение сбрасывается при смене сеанса, реконнекте и остановке,
а при долгом отсутствии pong считается устаревшим. Неподключённый профиль не
имеет измеримого WebRTC RTT; localhost SOCKS или TCP до сервиса видеосвязи не
выдаётся за задержку туннеля.

Текущая мобильная сборка запускает `jitsi` и `telemost` с `datachannel` или
`vp8channel`. `wbstream`, `seichannel` и `videochannel` не входят в этот runtime:
импорт явно отклоняет такие ссылки, не создавая неработающий профиль.

## Обоснование по CONSTITUTION 3.1

- владелец TarnVPN запросил загрузку olcRTC-подписки и её настройку;
- в поставляемом Android libbox и приложении olcRTC отсутствует;
- app-only адаптер официального mobile API дешевле переноса WebRTC в sing-box.

Точки касания core: `cmd/internal/build_libbox/main.go`, `go.mod`, `go.sum`.
Протокольные пакеты sing-box не меняются.

## Требования

1. Поддержать одиночный `olcrtc://` URI v1 и смешанную HTTPS-подписку.
2. Валидировать provider, transport, room, ключ и transport payload.
3. Создавать отдельный профиль на каждый olcRTC URI.
4. Запускать нативный runtime до sing-box и использовать защищённые сокеты.
5. Закрывать runtime при stop, ошибке старта, destroy и смене профиля.
6. Сохранить существующее безопасное обновление подписок.
7. Не логировать полный URI, room или ключ.

## Критерии приёмки

- parser-тесты покрывают transport, `sub.md` и ошибочные значения;
- Android unit tests проходят;
- обе AAR собираются одним gomobile runtime;
- `Libbox.checkConfig` принимает сгенерированный SOCKS5-профиль;
- реальный provider/device тест отмечается отдельно, а не заменяется сборкой.
