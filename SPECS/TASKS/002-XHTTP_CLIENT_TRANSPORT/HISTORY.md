# История архитектуры XHTTP

## 21 октября 2026: ограничение ожидания и передача владения

Синхронное ожидание RoundTrip с отменой контекста не гарантировало возврат:
HTTP/2 мог ждать shared dial, заблокированный на начальной записи preface.
Реальный HTTP/2 transport с net.Pipe, который не принимает preface, воспроизвёл
игнорирование истёкшего budget и отмены. Ограниченное ожидание вынесено в
handshake_budget.go; unbuffered handoff определяет единственного владельца
ответа, поздний/отклонённый ответ очищается отдельно. Физическими сокетами
по-прежнему владеет реестр и точечный retirement.

Отдельные регрессии выявили stale warm-state, наследование dial ctx
установленными upload-сессиями, неосвобождённый protocol Write, зависший
download после stream-up upload failure, обратный порядок cancel/body Close,
ожидание бесконечного тела packet-up ack и скрытие ошибки rejected response
очисткой тела. Lifecycle сопровождается в задаче 050.

Для общего остатка добавлены request ID и этапы TCP/HTTP2/headers/первого ответа
в slow/timeout WARN. Это уточняет, что прежний текст stale pooled connection
не устанавливал причину. Таймауты, pool size, wire format и server settings
не менялись. Установленная alpha.68 пока не проверена; задержка 6.099s из
пользовательского журнала не объявляется доказанным следствием этих дефектов.

## 19 октября 2026: локализация восстановления после таймаута

Прежний timeout-path заменял все восемь элементов пула и помечал их retired. Затем отсутствие входящих байтов дольше warm-бюджета позволяло закрыть молчащие сокеты всех заменённых участников. Это помогало освобождать соседние соединения после общей потери сети, но один отказ также мог оборвать исправные соединения с обычной паузой передачи.

Основание: журнал пользователя содержит два warm-timeout по 10 секунд и общий сброс пула, после первого закрыто семь сокетов. Локальный HTTP/2 A/B показал, что при отказе одного сокета семь молчащих исправных соседей продолжают передачу без общего retirement и закрываются при прежней общей процедуре. Состояние семи реальных сокетов и причина первого timeout этим не установлены.

Кандидат alpha.67 заменяет только участника, для которого получен timeout. Проверка идентичности под общим с reset mutex заменяет временной debounce; независимые отказы обрабатываются отдельно. Полный network reset остаётся общим и сохраняет очистку всех поколений. Это осознанно меняет прежнюю регрессию очистки молчащего соседа: такой сосед теперь должен либо получить собственный отказ, либо быть закрыт явным reset.

Таймауты 10/15 секунд, восемь элементов пула, отсутствие общего HTTP/2 ping и сохранение недавно принимающих сокетов отказавшего участника оставлены. Проверка установленного APK на реальном телефоне остаётся отдельной.
