## 🔧 Changed

### ⬆️ Upstream base: sing-box `v1.14.0` + 33 commits

- Was: `v1.14.0` + 16 (lx.34–lx.36). Now: 17 more upstream commits up to «Fix cronet-go» of 2026-09-12; upstream has not tagged them yet.

- Fork submodules follow: `wireguard-go` carries v0.0.6 on top of the AmneziaWG 2.x/3.x line, `sing-tun` merges v0.9.3 under the acceptLoop self-heal patch. All fork patches (AWG obfuscation, rebind on handshake give-up, acceptLoop self-heal, gvisor nil-guard) are intact and tested.
- Unchanged: configuration, build tags, Go toolchain (`go1.26.6`).

## 🐛 Fixed

### 😴 WireGuard/AWG endpoint went down on device sleep

- Was: every device pause (screen off, system sleep) put the WireGuard device down and the wake brought it back up — a full reconnect with a new handshake each time, on top of the network pause/wake.
- Now: the endpoint reacts only to network pause/wake. Device sleep leaves the tunnel as is; the idle-suspend and AWG guard state machines of the fork keep their own control over a suspended device.
- Scope: `wireguard` endpoint (plain WG and AmneziaWG). Upstream fix.

### 🍎 macOS: WireGuard endpoint stuck after a network change

- Was: on macOS the bind uses a socket connected to the single peer; after a network change (Wi-Fi ↔ Ethernet, VPN over VPN, sleep/wake with a new address) that socket could return `EADDRNOTAVAIL` / `ENETUNREACH` / `EHOSTUNREACH` / `ENETDOWN` / `EHOSTDOWN` on every send or receive and the endpoint stayed dead until a restart.
- Now: those errors mark the bind for reopening and the endpoint rebinds; `ECONNREFUSED` from an ICMP-unreachable peer is ignored and covered by the handshake retries. (`wireguard-go` v0.0.6)

### 🔁 Selector `interrupt_exist_connections` on routed connections — upstream's own fix

- Upstream now registers routed connections in the selector's interrupt group the same way the fork has since lx.25 (SPEC 064). The fork keeps its inbound-side wrapper as well, so nested groups and handler outbounds stay covered; a routed connection is now tracked from both sides, and one node switch closes it once. No behavioural change for users.

### 🐧 Linux: network monitor spinning after a netlink receive overrun

- Was: after a burst of route/link events the netlink socket overran (`ENOBUFS`) and the monitor loop spun at 100% CPU, on routers typically after a link flap.
- Now: the overrun is handled, the socket is drained and the monitor resumes. (`sing-tun` v0.9.3)

### 🐧 Linux: `auto_redirect` pre-match and L3 forwarding

- Pre-match rules evaluated the bypass verdicts of `auto_redirect` incorrectly, and a bypass rule with an `outbound` did not bypass in pre-match; L3-forwarded traffic through the TUN was affected as well. Both are fixed upstream and in `sing-tun` v0.9.3.

### 🐧 Linux: process rules matched the wrong socket

- `process_name` / `process_path` lookup could match a different socket of the same port on Linux, the path lookup failed after the daemon dropped privileges, and SOCKS UDP associate had no process attribution. All three are fixed.

### 🧱 Core crashed when the interface monitor is unavailable

- On systems where the default-interface monitor cannot start (restricted containers, some router builds) the core dereferenced a nil monitor and crashed; it now runs without it.

### 🧩 Smaller upstream fixes

- Direct inbound UDP on 32-bit Linux before kernel 5.1.
- `sing-box check` no longer shares the service registry with a running instance (a check could disturb the live daemon).
- JSON `omitempty` on HTTP and OpenVPN option fields (exported config no longer carries empty objects).
- Tailscale endpoint binds IPv6 sockets on Windows.
- Linux desktop daemon (`boxdd`): enabling insecure mode is authorised via PolicyKit.

## 🐛 Исправлено

### 😴 WireGuard/AWG-эндпоинт опускался на сон устройства

- Было: каждая пауза устройства (выключение экрана, сон системы) опускала WireGuard-устройство, пробуждение поднимало — полный реконнект с новым рукопожатием каждый раз, помимо паузы/пробуждения сети.
- Стало: эндпоинт реагирует только на паузу/пробуждение сети. Сон устройства туннель не трогает; автоматы idle-suspend и AWG-guard форка сохраняют собственный контроль над приостановленным устройством.
- Область: эндпоинт `wireguard` (чистый WG и AmneziaWG). Апстримный фикс.

### 🍎 macOS: WireGuard-эндпоинт застревал после смены сети

- Было: на macOS bind использует сокет, подключённый к единственному пиру; после смены сети (Wi-Fi ↔ Ethernet, VPN поверх VPN, сон/пробуждение с новым адресом) этот сокет мог отдавать `EADDRNOTAVAIL` / `ENETUNREACH` / `EHOSTUNREACH` / `ENETDOWN` / `EHOSTDOWN` на каждую отправку и приём, и эндпоинт оставался мёртвым до рестарта.
- Стало: эти ошибки помечают bind на переоткрытие, эндпоинт ребиндится; `ECONNREFUSED` от ICMP-unreachable пира игнорируется и покрывается повторами рукопожатия. (`wireguard-go` v0.0.6)

### 🔁 `interrupt_exist_connections` селектора на маршрутизируемых соединениях — собственный фикс апстрима

- Апстрим теперь регистрирует маршрутизируемые соединения в interrupt-группе селектора так же, как форк с lx.25 (SPEC 064). Форк оставляет и свою обёртку входящей стороны, чтобы вложенные группы и handler-аутбаунды остались покрыты; маршрутизируемое соединение теперь отслеживается с двух сторон, переключение узла закрывает его один раз. Для пользователя поведение не меняется.

### 🐧 Linux: сетевой монитор крутился после переполнения netlink-приёма

- Было: после всплеска событий маршрутов/линков netlink-сокет переполнялся (`ENOBUFS`), и цикл монитора крутился на 100% CPU — на роутерах обычно после флапа линка.
- Стало: переполнение обрабатывается, сокет вычитывается, монитор продолжает работу. (`sing-tun` v0.9.3)

### 🐧 Linux: pre-match `auto_redirect` и L3-форвардинг

- Pre-match-правила неверно учитывали bypass-вердикты `auto_redirect`, а bypass-правило с `outbound` в pre-match не обходило; страдал и L3-форвардинг через TUN. Оба починены в апстриме и `sing-tun` v0.9.3.

### 🐧 Linux: правила по процессу попадали не в тот сокет

- Поиск `process_name` / `process_path` на Linux мог сопоставить другой сокет того же порта, поиск пути не работал после сброса привилегий демоном, у SOCKS UDP associate не было атрибуции процесса. Все три починены.

### 🧱 Ядро падало при недоступном мониторе интерфейсов

- На системах, где монитор дефолтного интерфейса не стартует (ограниченные контейнеры, некоторые сборки роутеров), ядро разыменовывало nil-монитор и падало; теперь работает без него.

### 🧩 Мелкие апстримные фиксы

- Direct-инбаунд UDP на 32-битном Linux с ядром до 5.1.
- `sing-box check` больше не делит реестр сервисов с работающим инстансом (проверка могла задеть живой демон).
- JSON `omitempty` у полей опций HTTP и OpenVPN (экспорт конфига больше не несёт пустые объекты).
- Tailscale-эндпоинт биндит IPv6-сокеты на Windows.
- Linux-демон десктопа (`boxdd`): включение insecure-режима авторизуется через PolicyKit.
