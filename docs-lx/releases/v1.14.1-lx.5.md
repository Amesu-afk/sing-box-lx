One fix for REALITY nodes. A `short_id` longer than 16 hex characters used to crash the whole process with an index-out-of-range panic instead of being reported as a configuration error — `sing-box check` failed without a usable message, and a running instance died outright. Such a value is now rejected as `invalid short_id`, on both the client and the server side. Legal values, the wire format, configuration, the tag sets of desktop, router and AAR builds and the Go toolchain are unchanged.

## 🔧 Changed

- Unchanged: configuration, the wire format, the tag sets of desktop, router and AAR builds, the Go toolchain (1.26.8), the four submodules.
- Upstream base is unchanged — sing-box `v1.14.1`. Known drift at the cut: `upstream/stable` is 10 commits ahead, together with a `wireguard-go` bump to v0.0.7. The WireGuard changes require re-basing the `wireguard-go` fork submodule first, so the whole set is still deliberately left for a separate sync.

## 🐛 Fixed

### 💥 REALITY short_id longer than 16 hex characters crashed the process

- Was: `tls.reality.short_id` with more than 16 hex characters produced a panic — `index out of range [8] with length 8` — instead of a configuration error. `sing-box check` exited without a usable message; `run`, the library `Start` and a daemon config apply killed the **entire** process, so the whole VPN went down rather than one node reporting an error. An inbound `vless` with `tls.reality` on a server or router panicked at startup. This is upstream behaviour, present since REALITY was added in 2023 and still in upstream today.
- Now: the length is checked before the value is decoded, and an over-long `short_id` is reported as `invalid short_id` (on the server side with the index of the offending entry, matching the error next to it). The same fix applies to the outbound and the inbound side.
- Boundaries: legal values are unchanged — an empty string still means the zero short_id, and 1 to 16 hex characters are accepted as before. An odd length or a non-hex character still yields `decode short_id`, as it always did. The wire format is unchanged: `short_id` is still copied into the session id. The error text is deliberately kept as `invalid short_id`, because client-side guards match on it.
- Who was affected: LxBox and the launcher reject such a value themselves, so their users never saw this. It hit a bare core with a hand-written config, subscriptions carrying a malformed `sid=` with the client-side guard switched off, and server configs. ([SPEC 090](https://github.com/Leadaxe/sing-box-lx/blob/lx/SPECS/TASKS/090-REALITY_SHORT_ID_OVERFLOW_PANIC/SPEC.md))

## 🐛 Исправлено

### 💥 REALITY short_id длиннее 16 hex-символов ронял процесс

- Было: `tls.reality.short_id` больше 16 hex-символов давал панику `index out of range [8] with length 8` вместо ошибки конфигурации. `sing-box check` завершался без внятного сообщения; `run`, `Start` библиотеки и применение конфига демоном убивали **весь** процесс — падал VPN целиком, а не один узел с ошибкой. Inbound `vless` с `tls.reality` на сервере или роутере паниковал при старте. Это поведение апстрима: оно существует с появления REALITY в 2023 году и живо в апстриме до сих пор.
- Стало: длина проверяется до декодирования, и слишком длинный `short_id` отвергается как `invalid short_id` (на серверной стороне — с индексом проблемного элемента, в форме соседней ошибки). Правка сделана и для outbound'а, и для inbound'а.
- Границы: легальные значения не меняются — пустая строка по-прежнему означает нулевой short_id, 1…16 hex-символов принимаются как раньше. Нечётная длина или не-hex символ по-прежнему дают `decode short_id`. Провод не меняется: `short_id` так же копируется в идентификатор сессии. Текст ошибки намеренно оставлен прежним — `invalid short_id`, — потому что на него ориентируются клиентские гарды.
- Кого задевало: LxBox и лаунчер отбрасывают такое значение сами, поэтому их пользователи этого не видели. Било голое ядро с рукописным конфигом, подписки с мусорным `sid=` при отключённом клиентском гарде и серверные конфиги. ([SPEC 090](https://github.com/Leadaxe/sing-box-lx/blob/lx/SPECS/TASKS/090-REALITY_SHORT_ID_OVERFLOW_PANIC/SPEC.md))
