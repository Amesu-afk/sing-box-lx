The fork moves to upstream sing-box `v1.14.1`. This release carries upstream's own fixes and no fork behaviour changes: DNS queries that failed an exchange no longer bypass deduplication, the darwin OOM-killer timer stays stopped once stopped, iOS wakes the instance after a device pause, and dependency bumps fix a crash on a corrupted cache file, closed-connection errors on Windows and a Tailscale timer keeping a closed endpoint alive. Configuration, the wire format and the tag sets of desktop, router and AAR builds are unchanged.

Форк переходит на апстримный sing-box `v1.14.1`. В релизе — только апстримные исправления, изменений поведения форка нет: DNS-запросы после неудачного обмена больше не обходят дедупликацию, OOM-killer timer на darwin остаётся остановленным, iOS будит инстанс после паузы устройства, а бампы зависимостей чинят краш на битом файле кеша, распознавание ошибок закрытого соединения на Windows и таймер Tailscale, державший живым закрытый endpoint. Конфигурация, провод и наборы тегов desktop-, router- и AAR-сборок не меняются.

## 🔧 Changed

### ⬆️ Upstream base is now sing-box `v1.14.1`

- The fork was based on `v1.14.0` + 33 commits; it now sits on upstream `v1.14.1` plus two later commits. Drift against upstream is zero again.
- Version numbering follows the base: this release is `1.14.1-lx.1`, not `1.14.0-lx.40`. The `lx.N` counter restarts on each upstream line, as it did when the fork moved to 1.14.0. The previous line ends at `v1.14.0-lx.39`.
- Fork submodules (`wireguard-go`, `sing-tun`, `gvisor`) are unchanged — they already matched upstream before the merge.

### 🧰 Go toolchain 1.26.8

Builds now use Go 1.26.8, matching upstream. Go 1.27.1 exists; the fork deliberately tracks upstream's stable line rather than the newest release.

## 🐛 Fixed

### 🔁 Repeated DNS queries after a failed exchange

A DNS query whose exchange failed used to bypass deduplication, so identical queries could pile up instead of sharing one in-flight request. Waiters now share the result of a single exchange. The structured DNS query stream is unaffected: every requester still receives its own event, failures included.

### 🍎 OOM-killer timer restarting after being stopped on macOS

A memory-pressure callback could restart the OOM killer timer after it had been stopped.

### 📱 Instance not waking after a device pause on iOS

On iOS the current instance is now woken after the device pause ends.

### 💾 Crash on a corrupted cache file

A damaged cache file crashed the core on startup instead of being reported.

### 🪟 Closed-connection errors not recognised on Windows

Connections closed by the peer were not recognised as such on Windows, surfacing as unclear errors.

### 🔗 Tailscale timer keeping a closed endpoint alive

A netmap expiry timer kept a closed Tailscale endpoint alive.

### 🧭 Process name in the resolved fallback

The resolved fallback now reads the process name from `comm`.

## 🔧 Изменено

### ⬆️ База апстрима — sing-box `v1.14.1`

- Форк стоял на `v1.14.0` + 33 коммита; теперь — на апстримном `v1.14.1` плюс два коммита сверху. Дрейф от апстрима снова нулевой.

- Форк-сабмодули (`wireguard-go`, `sing-tun`, `gvisor`) не менялись — их версии совпадали с апстримом ещё до мержа.

### 🧰 Go-тулчейн 1.26.8

Сборки идут на Go 1.26.8 — как у апстрима. Go 1.27.1 существует; форк намеренно следует за stable-линией апстрима, а не за самым свежим выпуском.

## 🐛 Исправлено

### 🔁 Повторные DNS-запросы после неудачного обмена

DNS-запрос, обмен по которому завершился неудачей, обходил дедупликацию — одинаковые запросы могли накапливаться вместо того, чтобы разделить один уже идущий. Теперь ждуны разделяют результат одного обмена. Структурный поток DNS-запросов не затронут: каждый заявитель по-прежнему получает своё событие, включая ошибки.

### 🍎 OOM-killer timer перезапускался после остановки на macOS

Колбэк memory pressure мог перезапустить уже остановленный OOM-killer timer.

### 📱 Инстанс не просыпался после паузы устройства на iOS

На iOS текущий инстанс теперь пробуждается после окончания паузы устройства.

### 💾 Краш на битом файле кеша

Повреждённый файл кеша ронял ядро при старте вместо того, чтобы отдать ошибку.

### 🪟 Ошибки закрытого соединения не распознавались на Windows

Соединения, закрытые другой стороной, не распознавались как таковые на Windows и всплывали невнятными ошибками.

### 🔗 Таймер Tailscale держал живым закрытый endpoint

Netmap expiry timer удерживал живым уже закрытый Tailscale-endpoint.

### 🧭 Имя процесса в resolved-фолбэке

Resolved-фолбэк читает имя процесса из `comm`.
